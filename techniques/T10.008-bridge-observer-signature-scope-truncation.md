# OAK-T10.008 — Bridge Observer Signature Scope Truncation (DEPRECATED)

**Maturity:** deprecated
**Superseded by:** none — returned to [`TAXONOMY-GAPS.md`](../TAXONOMY-GAPS.md) as a candidate with no confirmed anchor
**Deprecated:** 2026-10-11

## Why this ID is deprecated

The Technique was minted from a single incident — THORChain, 2026-05-15 — using a third-party analysis published the day of the exploit. That analysis attributed the loss to a malicious proposer flipping an unsigned `direction` flag in Bifrost's `ObservedTx` wrapper, which observer signatures did not cover.

THORChain's own root-cause report (Exploit Report #2, 2026-07-03) attributes the loss to something else entirely: a malicious validator extracting a vault's private key through three weaknesses in THORChain's GG20 threshold-signing library, over 864 deliberately failed signing rounds. The report does not mention Bifrost, observers, or the direction flag. The incident is now mapped to **OAK-T10.001** — see [`examples/2026-05-thorchain-router-exploit.md`](../examples/2026-05-thorchain-router-exploit.md).

The weakness this Technique describes was real — THORNode patched it in a commit dated 2026-05-06 — but no exploitation of it is on record. A Technique with no confirmed incident does not meet OAK's bar; the mechanism is kept as a **TAXONOMY-GAPS candidate** and can be re-minted under a new ID if an exploitation is documented. The second example once attached to this ID (a cross-chain observer-signature audit cohort) was quarantined on 2026-10-11 for lack of any source.

The ID is retained and not reused, per `CONTRIBUTING.md`.

## The mechanism, kept for reference

A bridge observer network signs observations of external-chain events so that a consensus layer can act on them. If the signed payload covers only part of the observation, any field outside it — direction, destination, memo, migration slot — can be altered by whoever assembles the observation without invalidating the signatures. The defensive principle: **the bytes signed must equal the bytes that determine what the observation does.**

## What went wrong, for the record

The analysis was confident, detailed, and built on a real code change, and OAK recorded it as settled on the day of the exploit with an incident report marked "COMPLETE". It was never re-checked when the operator published. This is the same failure mode as the KelpDAO misclassification (2026-04-18, corrected 2026-09): an open investigation filed as a finding.
