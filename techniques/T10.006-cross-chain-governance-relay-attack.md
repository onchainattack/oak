# OAK-T10.006 — Cross-Chain Governance Relay Attack (DEPRECATED)

**Maturity:** deprecated
**Superseded by:** none — the incidents nearest to it are filed under [OAK-T10.002](./T10.002-message-verification-bypass.md), [OAK-T10.009](./T10.009-cross-chain-token-configuration-role-capture.md) and [OAK-T9.004](./T9.004-access-control-misconfiguration.md)
**Deprecated:** 2026-11-27

## Why this ID is deprecated

The Technique described a **governance message forged, replayed or relayed without proper verification**, so that an action the source-chain DAO never approved executes on a destination chain. The 2026-11-27 source passes found no incident of that shape.

- **Compound "cross-chain governance relay" (dated 2024-07)**, once its example. Its only source is OpenZeppelin's 2023 pre-deployment audit of Compound's Polygon bridge receiver, which reports no exploit. Quarantined.
- **Stake DAO vsdCRV (2026-05)** and **The Sandbox SAND (2026-08)**, the last two examples. Both are changes to a LayerZero OFT's configuration by whoever held the configuring authority, followed by an unbacked mint. No proposal existed and nothing was relayed. They are OAK-T10.009: see [`examples/2026-05-stake-dao-vsdcrv-layerzero-oft-peer-redirect.md`](../examples/2026-05-stake-dao-vsdcrv-layerzero-oft-peer-redirect.md) and [`examples/2026-08-sandbox-sand-layerzero-oft-delegate-hijack-unbacked-mint.md`](../examples/2026-08-sandbox-sand-layerzero-oft-delegate-hijack-unbacked-mint.md).
- A search for a forged or replayed cross-chain governance message found none.

With no documented incident behind it, the ID does not meet OAK's bar. The ID is retained and not reused, per `CONTRIBUTING.md`.

## What is real nearby

- **A forged cross-chain message that triggers a privileged action** is real, and in each documented case the privileged action was a bridge's own configuration, not a DAO vote. Poly Network (2021-08): a relayed transaction made the Ethereum-side manager replace the keeper keys ([`examples/2021-08-poly-network.md`](../examples/2021-08-poly-network.md)). Hyperbridge (2026-04): a forged request changed the admin of a bridged token ([`examples/2026-04-hyperbridge-merkle-proof-counterfeit-mint.md`](../examples/2026-04-hyperbridge-merkle-proof-counterfeit-mint.md)). Both are filed by how the message got through: OAK-T9.004 and OAK-T10.002.
- **Capture of a cross-chain token's configuration role** is OAK-T10.009.
- The audit finding behind the Compound file is a useful design point and belongs to mitigations: a proposal queued on the destination chain should be cancellable there.

If an incident is documented in which a governance action executed on a destination chain without source-chain approval, it goes to TAXONOMY-GAPS as a candidate and is minted under a new ID.

## What went wrong, for the record

The page was written from the design of cross-chain governance bridges, with a checklist of failure modes and no incident. Two later incidents were attached to it by surface similarity (a cross-chain token, a privileged change) and each file ended up saying in its own text that the Technique did not fit. Same failure as OAK-T9.012, OAK-T10.008, OAK-T16.003, OAK-T17.005, OAK-T7.006, OAK-T10.004, OAK-T16.004 and OAK-T7.010.
