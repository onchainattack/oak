# OAK-T10.004 — Optimistic-Bridge Fraud-Proof Gap (DEPRECATED)

**Maturity:** deprecated
**Superseded by:** none — [OAK-T10.002](./T10.002-message-verification-bypass.md) and [OAK-T10.001](./T10.001-validator-signer-key-compromise.md) cover the incidents once filed here
**Deprecated:** 2026-11-27

## Why this ID is deprecated

The Technique described an optimistic bridge that loses funds because **a fraudulent message or state root is not challenged in the dispute window**: watchers offline, no funded challengers, or a censored challenge. The 2026-11-27 source passes found no incident of that shape.

- **Nomad (2022-08-01)**, the anchor. Halborn, quoting Nomad's post-mortem, describes an upgrade on 2022-06-21 that made the zero root count as proven, so every message passed verification. No opened page reports a watcher or challenger failing. It is OAK-T10.002: see [`examples/2022-08-nomad-bridge.md`](../examples/2022-08-nomad-bridge.md). The separate "Nomad optimistic verification gap" file was a second entry for the same incident and is merged into it.
- **Arbitrum's permissioned validator set** and the **optimistic-bridge cohort** describe design properties, with no attack. Both were quarantined.
- **AFX Trade (2026-07-22)**. Five validator keys were compromised and the signatures were valid; CoinDesk reports that the contract released the funds after a 200-second dispute period. No opened page says whether anyone tried to challenge. It is OAK-T10.001: see [`examples/2026-07-afx-trade-bridge-hot-validator-key-quorum-compromise.md`](../examples/2026-07-afx-trade-bridge-hot-validator-key-quorum-compromise.md).

With no documented incident behind it, the ID does not meet OAK's bar. The ID is retained and not reused, per `CONTRIBUTING.md`.

## What is real nearby

- **Forged or wrongly accepted proofs** are OAK-T10.002; **stolen validator keys** are OAK-T10.001.
- **A dispute or veto window too short for anyone to act** is a real design weakness. AFX's 200 seconds is the documented example, and a secondary source says Hyperbridge's challenge period was set to zero when a forged proof was accepted in 2026-04. In both the loss has another root cause, so OAK records the window as a contributing condition on those examples, not as a Technique.
- Leads not yet read from a source: reports that NEAR's Rainbow Bridge watchdogs challenged fabricated blocks in 2022 (an attack on the dispute mechanism that failed), and L2BEAT's warnings about rollups with whitelisted challengers. A documented loss of this kind would be minted under a new ID.

## What went wrong, for the record

The page was built on a reading of the Nomad incident as a failure of optimistic verification, which the post-mortem does not support, and on essays about challenger incentives. Claims about unfunded challengers and unjustified windows were written as findings. Same failure as OAK-T9.012, OAK-T10.008, OAK-T16.003 and OAK-T17.005.
