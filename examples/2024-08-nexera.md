# Nexera — contract ownership taken with credentials stolen by a fake-job malware test, NXRA withdrawn — Ethereum — 2024-08-06

**Loss:** **~\$1.5M** of NXRA tokens, per [Halborn](https://www.halborn.com/blog/post/explained-the-nexera-hack-august-2024) and [Cointelegraph](https://cointelegraph.com/news/nexera-hack-1-5-million-nxra-token) (which relays a Cyvers alert of 2024-08-07). Halborn says Nexera then zeroed the attacker's token balances, "eliminating all but the approximately \$449K they had already stolen" ([Halborn](https://www.halborn.com/blog/post/explained-the-nexera-hack-august-2024)). The exact UTC time of the attack is undisclosed in the sources opened; the file name uses 2024-08-06 and the first public alert found is dated 2024-08-07.

**OAK Techniques observed:** **OAK-T11.014** (Operator Privileged-Key Compromise — *primary*): the attacker used stolen credentials that managed Nexera's smart contracts to transfer ownership of them and then take the tokens ([Halborn](https://www.halborn.com/blog/post/explained-the-nexera-hack-august-2024)). See [`techniques/T11.014-operator-privileged-key-compromise.md`](../techniques/T11.014-operator-privileged-key-compromise.md). **OAK-T15.001** (Social Engineering of Operator Personnel): an employee was approached about a part-time consulting job and told to clone and build a game from a GitHub repository as a skills test; the code carried malware ([Halborn](https://www.halborn.com/blog/post/explained-the-nexera-hack-august-2024)). See [`techniques/T15.001-social-engineering-of-operator-personnel.md`](../techniques/T15.001-social-engineering-of-operator-personnel.md).

**Attribution:** **inferred-weak**. Halborn says the investigation found the pretext and malware "part of the modus operandi for the Lazarus Group and similar threat actors" and calls the actor "believed to be the Lazarus Group or a similar organization"; no forensic evidence is shown ([Halborn](https://www.halborn.com/blog/post/explained-the-nexera-hack-august-2024)). ZachXBT, quoted by Cointelegraph, says the attacker is connected on-chain to earlier private-key compromises including SpaceCatch, Concentric Finance, OKX DEX, Serenity Shield and Reach ([Cointelegraph](https://cointelegraph.com/news/nexera-hack-1-5-million-nxra-token)).

**Key teaching point:** **One workstation held enough credentials to take ownership of the contracts and to block their upgrade and reassignment; ownership held by a multi-signature wallet, with hardware wallets for privileged accounts, removes that single point.** Halborn names exactly these two measures as ones Nexera planned after the incident ([Halborn](https://www.halborn.com/blog/post/explained-the-nexera-hack-august-2024)).

## Summary

A Nexera employee was approached about a consulting role and, as a skills test, cloned and built a game from a GitHub repository. The code ran malware that stole the login credentials used to manage Nexera's smart contracts ([Halborn](https://www.halborn.com/blog/post/explained-the-nexera-hack-august-2024)). The attacker transferred ownership of some contracts to themselves, blocked upgrades and reassignment of ownership, and drained about \$1.5M of tokens staked in the affected contracts ([Halborn](https://www.halborn.com/blog/post/explained-the-nexera-hack-august-2024)). Cyvers' alert, relayed by Cointelegraph, describes it as an address taking ownership of the proxy contract, upgrading it, and then using the withdraw admin function to move all NXRA tokens ([Cointelegraph](https://cointelegraph.com/news/nexera-hack-1-5-million-nxra-token)). Halborn calls the loss "tokens that were staked within affected contracts"; Cointelegraph's account is of NXRA tokens moved out of the proxy. The two sources do not give a contract-level breakdown.
