# Curve Finance — CowSwapBurner approved CoW orders without checking the order hash, so 138 forged orders sold DAO fee tokens to the attacker — Curve CowSwapBurner / Ethereum — 2026-11-10

**Loss:** **~\$38.2K** (38,205.76 USDC from 138 forged orders, per Curve's disclosure as relayed by DefiPrime and RektRadar; OAK's own sum of the 138 USDC transfers from the CoW settlement contract to the attacker address is 38,205.762103 USDC, `verified: oak`). Curve says "No user funds were affected"; pools, lending markets and crvUSD were not involved. The stolen proceeds were unrecovered at disclosure (DefiPrime). Treasury loss only; no reimbursement question arises. A **related earlier incident** (Balancer fee burner, 2026-10-24, about 0.64 ETH) is documented in its own section below.

**OAK Techniques observed:** **OAK-T10.002** (Message-Verification Bypass — *primary*, per Curve's report as quoted by DefiPrime and Bitquery. The burner's ERC-1271 `isValidSignature(orderHash, signature)` ignored the `_hash` it was given and validated only the order description attached as the signature, so CoW Protocol accepted forged orders. This is a business-logic check that was missing in an application-layer verifier, which is the T10.002 shape rather than a cryptographic flaw; see [`techniques/T10.002-message-verification-bypass.md`](../techniques/T10.002-message-verification-bypass.md)). **OAK-T7.007** (DEX Aggregator Routing Laundering — USDC swapped to ETH through aggregator routes). **OAK-T7.003** (Cross-Chain Bridge Laundering — ETH sent to the LI.FI Diamond; Curve reports onward bridging to Arbitrum and a Hyperliquid deposit). **OAK-T7.001** (Mixer-Routed Hop — gas funded from a Railgun withdrawal per Bitquery; 0.3 ETH sent to Tornado Cash on 2026-11-15).

**Attribution:** **unattributed** (receiver of the forged orders: [`0x356e0178b0f07fe7d97c3a61e502ce52bc5564b8`](https://etherscan.io/address/0x356e0178b0f07fe7d97c3a61e502ce52bc5564b8)). Bitquery found no link between the Curve and Balancer attackers and attributes neither to anyone.

**Key teaching point:** **A contract that approves orders through ERC-1271 must compare the order hash it is asked about with the order it actually authorised; a check on a user-supplied "description" alone is not a check on what the settlement contract will execute.** Curve's burner confirmed that the attached description looked like one of its own orders but never confirmed that the attached description produced the hash being signed.

## Summary

Curve's CowSwapBurner ([`0xc0fc3ddfec95ca45a0d2393f518d3ea1ccf44f8b`](https://etherscan.io/address/0xc0fc3ddfec95ca45a0d2393f518d3ea1ccf44f8b)) has converted DAO fee tokens to crvUSD through CoW Protocol since June 2024. It posts standing orders to sell fee tokens for crvUSD to the FeeCollector ([`0xa2bcd1a4efbd04b63cd03f5aff2561106ebcce00`](https://etherscan.io/address/0xa2bcd1a4efbd04b63cd03f5aff2561106ebcce00)) and, when CoW's settlement contract asks it to confirm an order by ERC-1271, it checked the order description attached to the signature, not the order hash. On 2026-11-10 from 00:07 UTC an attacker used that gap to settle 138 forged orders that sold the burner's accumulated tokens for USDC paid to [`0x356e0178b0f07fe7d97c3a61e502ce52bc5564b8`](https://etherscan.io/address/0x356e0178b0f07fe7d97c3a61e502ce52bc5564b8). Curve received an external vulnerability report at about 12:40 UTC, and its Emergency DAO disabled the burner at 13:59 UTC. Curve disclosed on 2026-11-17. Curve reports that it reviewed 6,558 settled burner orders since deployment; only the forged ones paid anywhere other than the FeeCollector.

## Related earlier incident: Balancer fee burner, 2026-10-24

Bitquery reports that Balancer's v3 fee burner on Ethereum ([`0x9958317b80ee5f10457017d54c2484d722059157`](https://etherscan.io/address/0x9958317b80ee5f10457017d54c2484d722059157)) was drained by the same class of flaw 17 days earlier. The burners sell collected fees through CoW Swap and approve orders via ERC-1271; the check "never checked that the copy was the order that CoW was about to fill" (Bitquery), and Balancer's `verify` receives the order hash without a name, so the code cannot read it. The attacker posted forged orders and attached a copy of one real order as the signature on each.

- **Loss:** about 0.64 ETH, about \$1,512 at an ETH price of \$2,380 (Bitquery), in 26 forged orders filled in 17 minutes. OAK sums the 26 ETH transfers from the CoW settlement contract to the attacker at about 0.6353 ETH (`verified: oak`); first forged order [`0x9789073eeb82d1b77c2ae4f96c22e22c63f5b82fb2f25838f72f6f80127416b4`](https://etherscan.io/tx/0x9789073eeb82d1b77c2ae4f96c22e22c63f5b82fb2f25838f72f6f80127416b4) (2026-10-24 02:13:59 UTC), last [`0x840938c698334aae5cbf414024f114d833d2084499450bf7ca929bb8654ec981`](https://etherscan.io/tx/0x840938c698334aae5cbf414024f114d833d2084499450bf7ca929bb8654ec981) (02:30:35 UTC), receiver [`0x33b80a1fe45b3307c0c5665abd2408167d731c54`](https://etherscan.io/address/0x33b80a1fe45b3307c0c5665abd2408167d731c54).
