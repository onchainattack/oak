# Pike Finance — forged CCTP message, then an upgrade that erased the initialization flag — Pike spoke contracts / Ethereum, Arbitrum, Optimism — 2024-04-26 and 2024-04-30

**Loss:** two separate exploits. 2024-04-26: \$299,107 on Arbitrum ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)); Cointelegraph rounds it to \$300,000 ([Cointelegraph](https://cointelegraph.com/news/pike-finance-exploited-1-6-million-second-exploit-3-days)). 2024-04-30: \$1,983,633.18 by CertiK's loss table (Arbitrum \$100,070.00, Ethereum \$1,433,977.23, Optimism \$150,458.95) ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)). The sources disagree on the 04-30 total: CertiK's text and Cointelegraph give \$1.68M ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis), [Cointelegraph](https://cointelegraph.com/news/pike-finance-exploited-1-6-million-second-exploit-3-days)). Pike offered a 20% reward for return of funds or information leading to recovery ([Cointelegraph](https://cointelegraph.com/news/pike-finance-exploited-1-6-million-second-exploit-3-days)). No recovery is reported in the sources opened.

**OAK Techniques observed:** **OAK-T10.002** (Message-Verification Bypass — *primary for the 04-26 exploit*). Per the project's own statement as relayed by CertiK, the root cause was a forged CCTP message that let the attacker drain funds; CertiK does not independently verify it ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)). See [`techniques/T10.002-message-verification-bypass.md`](../techniques/T10.002-message-verification-bypass.md). **OAK-T9.004** (Access-Control Misconfiguration — *primary for the 04-30 exploit*). An upgrade that added `pause()` and `unpause()` changed the storage layout so that the initialization flag was zeroed; the attacker called `initialize()` again, took the role it sets, and upgraded the proxy with `upgradeToAndCall()` ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)). See [`techniques/T9.004-access-control-misconfiguration.md`](../techniques/T9.004-access-control-misconfiguration.md). **OAK-T7.001** (Mixer-Routed Hop) and **OAK-T7.003** (Cross-Chain Bridge Laundering) for the funds ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)).

**Attribution:** **unattributed**. CertiK names no person; it traces wallets through Tornado Cash, Railgun, Orbiter, Stargate and Li.Fi ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)). Whether the two exploits were the same actor is not stated in the sources opened.

**Key teaching point:** **An upgrade that touches storage must be tested for its effect on the initialization flag before it is deployed, and a contract that has no pause switch needs one before it is attacked, not during.** Pike's first response to the 04-26 exploit was a pause upgrade, because the contract had no pause function; CertiK says that upgrade assigned 0 bytes to the initialization flag and erased its state, which made the second exploit possible ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)). CertiK calls this "a rare case of a reaction to one exploit leading to the cause of a second exploit" ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)).

## Summary

On 2024-04-26 an attacker drained \$299,107 from Pike on Arbitrum; per the project this was a forged CCTP message ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)). The contract had no pause function, so Pike had to upgrade it to add `pause()` and `unpause()`; the original implementation is [`0x634683d7079af2EBeC84637BBC29dbD6FE817564`](https://etherscan.io/address/0x634683d7079af2EBeC84637BBC29dbD6FE817564) and the new one [`0xD167A1893e8F108572826dAbAe19663A9131b0c2`](https://etherscan.io/address/0xD167A1893e8F108572826dAbAe19663A9131b0c2) ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)).

CertiK explains the second exploit as a storage collision: the new functions return a bool that was packed into a storage slot with unused space, which differed from the original layout, and "the upgrade assigned 0 bytes to the initialization flag, erasing its state" ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)). The contract then behaved as if it had never been initialized ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis), [Cointelegraph](https://cointelegraph.com/news/pike-finance-exploited-1-6-million-second-exploit-3-days)). On 2024-04-30 the attacker called `initialize()` on the proxy, which set the `isActive` variable to the attacker's address, then called `upgradeToAndCall()` to move the proxy to a malicious implementation, withdrew 479.39 ETH, and repeated this on Arbitrum and Optimism ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)). CertiK notes the contract had stayed paused during this exploit ([CertiK](https://www.certik.com/blog/pike-finance-incident-analysis)). Pike attributed both incidents to a single flaw ([Cointelegraph](https://cointelegraph.com/news/pike-finance-exploited-1-6-million-second-exploit-3-days)). Pike's own post-mortem could not be opened (403), so the account here rests on CertiK and Cointelegraph.

## Root-cause evidence

- **Technique:** OAK-T9.004 (04-30); OAK-T10.002 (04-26)
- **Source:** <https://www.certik.com/blog/pike-finance-incident-analysis>; <https://cointelegraph.com/news/pike-finance-exploited-1-6-million-second-exploit-3-days>
- **Source type:** security-firm
- **Confidence:** reported
- **Evidence:** CertiK gives the 04-30 mechanism in detail (re-callable `initialize()`, storage-layout change from the pause upgrade, `upgradeToAndCall()`), and Cointelegraph relays Pike's statement that the contract behaved as if uninitialized. For 04-26, CertiK only repeats the project's "forged CCTP message" statement without verifying it; how the message was forged is undisclosed. Pike's post-mortem on mirror.xyz returned 403 and was not read. The 04-30 total differs between CertiK's text (\$1.68M) and its loss table (\$1,983,633.18).
