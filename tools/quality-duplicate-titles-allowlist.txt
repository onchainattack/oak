#
# check_quality's D1 detector fuzzy-matches example H1s. Most of what it finds
# is legitimate: the same protocol hit twice years apart, a cohort file whose
# window overlaps another's, or one incident deliberately filed under two
# Technique framings. This file records the review verdict for each pair so the
# detector can stay a hard gate and a genuinely new duplicate still fails CI.
#
# It is a review ledger, not a mute button. Three verdicts:
#
#   distinct    — different incidents. Similar names, nothing else shared.
#   framing     — one incident, separate files by Technique framing, facts
#                 cross-checked as consistent between them.
#   unreviewed  — one incident in more than one file, the split looks deliberate,
#                 but the files' facts have NOT been cross-verified against each
#                 other or against sources. Passes the gate; owed a review.
#
# Format: <verdict> <TAB> <file A> <TAB> <file B> <TAB> # note
